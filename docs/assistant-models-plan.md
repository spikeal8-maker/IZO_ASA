# Голос и улучшение промптов

Статус: рабочий контракт и план следующих runtime. Модель считается доступной только при успешном health-check; справочный кандидат не попадает в рабочий список автоматически.

## Оборудование

- RTX 3090: только генерация изображений.
- RTX 4070 12 ГБ: локальная транскрибация и улучшение промптов.
- Intel Core i5 10-го поколения и 30 ГБ RAM: backend и временный CPU-режим до установки RTX 4070.

## Целевая маршрутизация

1. Голос обрабатывает специализированная ASR-модель.
2. Кнопка «Голос» возвращает расшифровку без изменения смысла.
3. Кнопка «Улучшить» отдельно передаёт готовый текст в Gemma 4 12B.
4. Локальный worker используется, пока он здоров и его очередь укладывается в лимит ожидания.
5. При timeout, OOM, ошибке health-check или перегрузке конкретная операция уходит в OpenRouter.

## Кандидаты

- ASR: Qwen3-ASR 1.7B и Faster Whisper Large V3 Turbo должны пройти одинаковый русский тестовый набор.
- Лёгкий ASR: Qwen3-ASR 0.6B.
- CPU-авария: Whisper Medium INT8.
- API ASR: Gemini 3.1 Flash Lite Audio; GPT Audio Mini как второй провайдер.
- Локальное улучшение: Gemma 4 12B Q4.
- API улучшение: DeepSeek V4 Flash. Эта модель принимает текст, но не аудио.

## Условия допуска в production

- тест русской речи на тихом, шумном и мобильном микрофоне;
- отсутствие текста на тишине;
- корректная обработка WebM/Opus;
- timeout и circuit breaker;
- отдельные очереди ASR и prompt improvement;
- журнал задержки, ошибок, выбранного маршрута и фактической API-стоимости;
- отсутствие списания пользовательских токенов при неуспешной операции.

## DeepSeek: первый подключённый этап

- Endpoint: `POST /api/tools/improve-prompt`.
- Provider: OpenRouter, модель по умолчанию `deepseek/deepseek-v4-flash`.
- Модель и timeout переопределяются через `PROMPT_IMPROVE_MODEL` и `PROMPT_IMPROVE_TIMEOUT_SECONDS`.
- Запрос доступен только trusted-сессии, возвращает structured JSON и не запускает генерацию изображения.
- Исходный промпт не пишется в продуктовую аналитику; сохраняются только режим, длины, задержка, модель и стоимость.
- Интерфейс меняет поле только после успешного ответа. После замены кнопка показывает `Улучшено` и остаётся неактивной, пока пользователь не изменит текст.

## Управление в админке

В `Модели` помощники разделены на две самостоятельные вкладки:

- `Голосовой ввод`: отдельный рабочий экран трёх провайдеров, их статусов, маршрута и контрольной расшифровки аудиофайла.
- `Улучшение промпта`: рабочая конфигурация локальной Ollama и OpenRouter API.

Конфигурация помощников хранится в `admin_settings.assistant_models`. Голосовая часть содержит:

- маршрут `local`, `qwen`, `api` или `auto`;
- модель Ollama;
- отдельные `qwenModel` и `qwenBaseUrl` для Qwen ASR;
- резервную модель OpenRouter;
- минимальную длительность записи и timeout.

Конфигурация улучшения содержит:

- маршрут `api`, `local` или `auto`;
- Ollama-модель и OpenRouter-модель;
- отдельные timeout;
- главный системный промпт;
- режимные инструкции для каждой вкладки редактора;
- тестовые вызовы Ollama и OpenRouter из админки.

На текущем сервере `gemma4:12b` установлена в Ollama (GGUF, Q4_K_M, около 7.6 ГБ). Контрольный запуск при занятой RTX 3090 занял около 102 секунд, поэтому эту локальную модель нельзя включать в production до установки отдельной RTX 4070.

`gemma4:31b-cloud` через Ollama успешно прошла контрольный русский запрос примерно за 2 секунды. Стартовый маршрут установлен как `auto`: сначала Ollama Cloud, а при timeout или ошибке — DeepSeek V4 Flash через OpenRouter. Бесплатные лимиты Ollama Cloud определяются сервисом Ollama и не считаются гарантированной мощностью проекта.

Каталог моделей OpenRouter загружается из живого `/models` API. В админском списке рядом с каждой моделью отображается цена входных и выходных токенов за 1 миллион.

Все стандартные системные и режимные инструкции отображаются и отправляются на русском языке. Для английского профиля к инструкции добавляется требование вернуть результат на английском. Parser принимает структурированный ответ OpenRouter как строку, объект, `parsed`, массив content-блоков или arguments tool-call, поэтому изменение формы ответа провайдера не должно обрушать пользовательскую операцию.

Админка дополнительно показывает итоговые сообщения `system` и `user`, фактически отправляемые модели для выбранного режима. Это позволяет видеть автоматически добавляемые требования языка и JSON, а не только редактируемые фрагменты.

## Первый рабочий голосовой маршрут

- Браузерный `MediaRecorder` записывает WebM/Opus или OGG/Opus и отправляет файл в защищённый `POST /api/tools/transcribe`.
- Админская проверка поддерживает два равноправных сценария: запись с микрофона с таймером и автоматической отправкой после `Стоп`, либо загрузку WAV/WebM/OGG/MP3/M4A до 8 МБ.
- Выбранная в интерфейсе карточка маршрута сразу определяет провайдера теста, даже если настройки ещё не сохранены. Это исключает проверку старого серверного маршрута.
- Backend передаёт аудио модели OpenRouter с аудиовходом; стартовая модель — `google/gemini-3.1-flash-lite`.
- Каталог OpenRouter запрашивается с фильтрами `input_modalities=audio` и `output_modalities=text`. В выпадающий список попадают только аудиосовместимые модели с неотрицательной ценой входа и выхода.
- Контрольный русский WAV успешно распознан моделью `google/gemini-3.1-flash-lite`; ответ совпал с исходной фразой, стоимость вызова составила `$0.0001075` при 199 токенах.
- Минимальная длительность управляется из админки и по умолчанию равна 1 секунде. Backend независимо проверяет длительность, пустой файл, формат и предел 8 МБ.
- Расшифровка добавляется к текущему промпту только после успешного ответа. При ошибке уже введённый текст сохраняется.
- Qwen3-ASR имеет готовый HTTP-адаптер, health-check и тестовый endpoint, но не считается работающим до запуска отдельного runtime и русского benchmark.

## Локальный аудиомаршрут Ollama

- `gemma4:12b` проверена реальным русским WAV: фраза распознана точно.
- Холодный контрольный запуск занял 26,85 сек., включая 18,65 сек. загрузки модели; поэтому timeout локального маршрута по умолчанию равен 45 сек., а модель удерживается в памяти 5 минут.
- Браузерные WebM/Opus и OGG/Opus нормализуются сервером через `imageio-ffmpeg` в WAV PCM16, 16 кГц mono.
- Доступные маршруты: `local`, `qwen`, `api`, `auto`. В `auto` порядок резерва: Qwen ASR, Ollama, OpenRouter.
- Аудиосовместимые Gemma 4: E2B, E4B и 12B Unified. Варианты 26B и 31B, включая `31b-cloud`, не используются для транскрибации.
- В админке показаны установленные совместимые модели и кандидаты Qwen3-ASR/Faster Whisper для будущего сравнения.

## Отдельный runtime Qwen3-ASR

- `Qwen/Qwen3-ASR-1.7B` не является моделью Ollama и не должна храниться в `localModel`.
- На Windows используется официальный пакет `qwen-asr==0.0.6` с Transformers-backend. vLLM-сервер нативно не используется.
- Изолированное CUDA-окружение находится в `.tools/qwen-asr-venv`, ASCII junction — `C:\izo-qwen-asr`, кеш весов — `C:\izo-qwen-cache`. ASCII-пути обязательны из-за ограничения зависимости `nagisa/DyNet` на Windows.
- Runtime `tools/qwen_asr_service.py` предоставляет OpenAI-совместимые `/v1/models` и `/v1/chat/completions`.
- Backend-порт по умолчанию: `http://127.0.0.1:8001`; он настраивается в админке.
- Запуск: `powershell -File tools/start-qwen-asr.ps1`. Остановка: `powershell -File tools/stop-qwen-asr.ps1`. PID реального Python-сервера хранится в `.tools/qwen-asr.pid`, PID удерживающего Windows-процесса — в `.tools/qwen-asr-wrapper.pid`, вывод — в `logs/qwen-asr.*.log`.
- Старое сохранённое значение `localModel=qwen3-asr:1.7b` автоматически нормализуется в `gemma4:12b`, чтобы не показывать несуществующую Ollama-модель.
- На текущей RTX 3090 Qwen3-ASR 1.7B проверен русским WAV через штатный backend-адаптер: точная расшифровка, первый inference 4,83 сек., тёплый 1,71 сек., видеопамять runtime около 4,6 ГБ. Полный холодный запуск с загрузкой весов может занимать около минуты; стартовый скрипт ждёт зелёный `/health` до 90 секунд.
- Принудительный `sdpa` на текущем Windows/CUDA runtime зависал внутри generation; сервис использует штатную attention-конфигурацию официальной модели.
- Перед первым тестовым запуском ComfyUI-модели были выгружены при пустой очереди. До установки отдельной RTX 4070 одновременная загрузка тяжёлого ComfyUI workflow и Qwen требует контроля свободной VRAM.
- После установки RTX 4070 Qwen3-ASR 1.7B и 0.6B проходят один benchmark: чистая речь, шум, паузы, мобильный микрофон, отсутствие галлюцинаций на тишине и p95 задержки.
