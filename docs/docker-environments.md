# Docker-профили IZO_ASA: исходники, стенд, рабочая поставка

Срез исходников: 17.10.2026. Это уточнение областей применения
[контракта приёмки](docker-delivery-acceptance.md), не альтернативная очередь задач.
Текущий пакет и ссылки на кандидата определяет [NOW.md](NOW.md).

## Профили нельзя смешивать

| Профиль | Источник | Ресурсы и доступ | Статус доказательства |
|---|---|---|---|
| DEV/TEST | `ops/docker/dev/compose.yml` в main | Отдельный `IZO_COMPOSE_PROJECT`, метки `io.izo.*`, network none по умолчанию | Ранее принятая основа; не работающий production |
| Shadow | Кандидат PR #186, SHA `8772a1100a40e6fed22578e9571250aefda5597f` | Префикс `izo-asa-shadow-`, метки `io.izo.*`, loopback 48125/48126 по умолчанию | Исходники подготовлены; итоговая контейнерная приёмка не подтверждена |
| Рабочая поставка | Будущий этап #126 | Compose `isoas`, метки `io.isoas.project=ISOAS` и `io.isoas.public-url`; желательный порт 5200 только после проверки занятости | Требование, не объявление готовности |
| Одноразовая приёмка целевой поставки | Будущий согласованный профиль | Уникальные `isoas-ci-<run-id>-<attempt>` | Каждый прогон имеет собственные данные и доказательства |

Старые имена DEV/Shadow не нужно исправлять переименованием уже работающих
контейнеров. Они обозначают переходный тестовый контур; production-норматив
применяется к согласованной новой поставке. Чужие проекты не трогать.

## Границы кандидата Shadow

В исходном CLI кандидата порты допускаются в диапазоне 20000–65535, поэтому
5200 не является параметром его текущего запуска. Используется Docker context
`desktop-linux`; это Windows Docker Desktop путь, не универсальный Linux CLI.
Отдельный Linux-адаптер из PR #183 находится в интеграционном кандидате, но
его присутствие не доказывает реальный запуск и сетевую приёмку на Linux.

В этом профиле web, backend и guard используют общую защищённую сетевую область;
внешние провайдеры и рабочие секреты отключены. Mock-генерация не подтверждает
доступность настоящих моделей. Не ослаблять изоляцию для получения зелёного теста.
Кандидатные файлы и инструкция: [PR #186](https://github.com/spikeal8-maker/IZO_ASA/pull/186).
Не искать ещё не принятые файлы кандидата как гарантированно имеющиеся в main.

## Что требуется перед переносом

ComfyUI, Ollama, Qwen ASR могут оставаться отдельными host-native службами.
Для каждой нужен явный адрес, разрешённый сетевой путь и отдельное испытание;
localhost контейнера не означает хост. TTS/Windows-функции не исключать молча.

Для перехода обязательны точный SHA/образы, контейнерные пользовательские цепочки,
восстановление SQLite и media, однократные списания/возвраты, матрица функций,
проверенные секреты и репетиция отката. Ни эта таблица, ни unit tests не закрывают
Д0–Д4. Реальные данные и трафик переводятся только после разрешения владельца.
