# Qwen3-ASR: установка, эксплуатация и перенос

Этот документ является рабочей инструкцией для локального сервиса распознавания
речи Qwen3-ASR. Он нужен для повторения установки на новом сервере без доступа к
истории чатов и ручным настройкам текущей машины.

## 1. Назначение и границы

Qwen3-ASR обслуживает кнопку голосового ввода в студии. Браузер записывает аудио,
backend нормализует его в WAV и отправляет в локальный OpenAI-совместимый сервис:

```text
браузер -> backend :8000 -> Qwen3-ASR :8001 -> текст -> поле промпта
```

Сервис Qwen:

- слушает только `127.0.0.1:8001`;
- предоставляет `GET /health`, `GET /v1/models` и `POST /v1/chat/completions`;
- последовательно обрабатывает запросы одним экземпляром модели;
- не является моделью Ollama и не хранится в поле `localModel`;
- может использоваться как основной маршрут `qwen` или как первый маршрут `auto`.

Порт `8001` нельзя публиковать в интернет: у локального runtime нет собственной
авторизации. Внешние запросы должны проходить только через основной backend.

## 2. Источник модели и лицензия

- Код и официальная инструкция: <https://github.com/QwenLM/Qwen3-ASR>
- Модель: <https://huggingface.co/Qwen/Qwen3-ASR-1.7B>
- Идентификатор: `Qwen/Qwen3-ASR-1.7B`
- Проверенная ревизия: `7278e1e70fe206f11671096ffdd38061171dd6e5`
- Лицензия модели: Apache-2.0
- Используемый Python-пакет: `qwen-asr==0.0.6`

При первом запуске пакет загружает веса с Hugging Face автоматически. Веса,
виртуальное окружение и кеш не коммитятся в Git.

Это проверенная, а не минимально возможная конфигурация. Для переноса следует
оставить не менее 8 ГБ свободного диска и не менее 6 ГБ свободной VRAM. Если Qwen
делит GPU с ComfyUI, перед запуском нужно проверить очередь и свободную память.

Официальная инструкция сейчас рекомендует новое изолированное окружение Python
3.12. Проект фактически проверен на Python 3.11.9, который закреплён для основного
репозитория. Переход на 3.12 выполняется только отдельным тестом, не попутным
обновлением production.

## 4. Что хранится в репозитории

- `tools/qwen_asr_service.py` — OpenAI-совместимый Transformers runtime.
- `tools/qwen-asr-requirements.txt` — проверенные верхнеуровневые версии.
- `tools/start-qwen-asr.ps1` — запуск и ожидание готовности.
- `tools/stop-qwen-asr.ps1` — остановка Python и удерживающего процесса.
- `tools/test_qwen_asr_service.py` — тест разбора запросов.
- `backend/app/integrations/qwen_asr.py` — backend-клиент сервиса.
- `backend/test_integrations_qwen_asr_module.py` — контрактные тесты клиента.

Локальные данные находятся вне Git:

| Путь | Содержимое |
| --- | --- |
| `.tools/qwen-asr-venv` | виртуальное окружение Python |
| `C:\izo-qwen-asr` | ASCII junction на окружение |
| `C:\izo-qwen-cache` | веса и кеш Hugging Face |
| `.tools/qwen-asr.pid` | PID реального Python-сервера |
| `.tools/qwen-asr-wrapper.pid` | PID удерживающего PowerShell |
| `logs/qwen-asr.out.log` | HTTP-журнал |
| `logs/qwen-asr.err.log` | загрузка модели и ошибки |

## 5. Требования перед установкой

1. Репозиторий клонирован в рабочую папку.
2. Установлен 64-битный Python 3.11.9.
3. `nvidia-smi` видит NVIDIA GPU и показывает свободную VRAM.
4. Сервер имеет доступ к PyPI, `download.pytorch.org` и Hugging Face.
5. На диске C: доступно не менее 8 ГБ.
6. Порт `127.0.0.1:8001` свободен.
7. Очередь ComfyUI пуста перед первой загрузкой модели на общей GPU.

Проверка:

```powershell
python --version
nvidia-smi
Get-NetTCPConnection -LocalPort 8001 -State Listen -ErrorAction SilentlyContinue
```

Если новый сервер использует другую CUDA/PyTorch-связку, нельзя молча менять
версии. Сначала обновляется отдельная тестовая установка, выполняется живой WAV-
тест, затем новое проверенное значение фиксируется в манифесте и этой таблице.

## 6. Чистая установка на Windows

Запускать из корня репозитория:

```powershell
python -m venv .tools\qwen-asr-venv
& .\.tools\qwen-asr-venv\Scripts\python.exe -m pip install --upgrade pip
& .\.tools\qwen-asr-venv\Scripts\python.exe -m pip install -r tools\qwen-asr-requirements.txt
```

После установки запустить runtime. Если ComfyUI не запущен или Qwen уже назначен
на отдельную машину, достаточно обычной команды:

```powershell
.\tools\start-qwen-asr.ps1
```

На сервере, где одновременно работает ComfyUI, GPU для Qwen указывается явно:

```powershell
# Пример после установки RTX 4070 как второго CUDA-устройства.
.\tools\start-qwen-asr.ps1 -CudaVisibleDevices "1"
```

Без явного GPU скрипт откажется запускать Qwen при активном ComfyUI. Это защита от
исчерпания VRAM и зависания очереди генерации. Для короткого контролируемого теста
на общей RTX 3090 сначала убедиться, что очередь пуста, и только затем использовать:

```powershell
.\tools\start-qwen-asr.ps1 -AllowSharedGenerationGpu
```

Этот флаг не предназначен для постоянной production-работы.

Стартовый скрипт:

1. проверяет наличие окружения;
2. запрещает неявное совместное использование GPU с работающим ComfyUI;
3. создаёт `C:\izo-qwen-asr` как ASCII junction;
4. назначает кеш `C:\izo-qwen-cache`;
5. передаёт проверенную ревизию модели и выбранный GPU в runtime;
6. запускает скрытый PowerShell и дочерний Python;
7. ждёт зелёный `/health` до 90 секунд;
8. сохраняет оба PID.

Первый запуск скачивает примерно 4,4 ГБ весов и поэтому может быть заметно
дольше повторного. Не прерывать загрузку без необходимости.

## 7. Настройка в админке

В `Админ -> Модели -> Голосовой ввод` используются:

| Настройка | Значение |
| --- | --- |
| Маршрут | `Qwen ASR` для прямого теста или `Авторезерв` для production |
| URL Qwen ASR | `http://127.0.0.1:8001` |
| Модель | `Qwen/Qwen3-ASR-1.7B` |
| Тайм-аут | 30 секунд рекомендуется для первого production-теста |
| Минимальная запись | 1 секунда |

В режиме `auto` порядок сейчас такой: Qwen ASR, локальная аудиомодель Ollama,
OpenRouter. Резерв включается только после ошибки текущего провайдера.

## 8. Проверка после установки

Проверить процесс и модель:

```powershell
Invoke-RestMethod http://127.0.0.1:8001/health
Invoke-RestMethod http://127.0.0.1:8001/v1/models
Get-NetTCPConnection -LocalPort 8001 -State Listen
```

Ожидаемый `/health`:

```json
{
  "ok": true,
  "model": "Qwen/Qwen3-ASR-1.7B",
  "revision": "7278e1e70fe206f11671096ffdd38061171dd6e5",
  "cuda": true,
  "device": "NVIDIA GeForce RTX 3090"
}
```

Затем в админке загрузить или записать русский аудиофрагмент и выполнить тест
маршрута Qwen. Финальная проверка выполняется пользовательской кнопкой `Голос`:
распознанный текст должен попасть в текущее поле промпта без перезагрузки страницы.

Репозиторные проверки:

```powershell
python -m pytest tools/test_qwen_asr_service.py backend/test_integrations_qwen_asr_module.py -q
.\tools\verify.ps1 -Mode Quick
```

## 9. Остановка и повторный запуск

```powershell
.\tools\stop-qwen-asr.ps1
.\tools\start-qwen-asr.ps1
```

`start-qwen-asr.ps1` идемпотентен: если порт уже слушается, второй экземпляр не
создаётся. `stop-qwen-asr.ps1` останавливает listener и PowerShell-wrapper.

После перезагрузки Windows сервис пока запускается вручную. Перед добавлением
автозапуска нужно выбрать и задокументировать сервисный аккаунт, рабочую папку,
политику перезапуска и порядок запуска относительно ComfyUI.

## 10. Известные проблемы и решения

### `Qwen ASR environment is missing`

Не создано `.tools/qwen-asr-venv`. Повторить раздел чистой установки.

### Белый статус или `Connection refused` на порту 8001

Проверить listener и `logs/qwen-asr.err.log`. Не переключать админский маршрут
на Qwen до зелёного `/health`.

### `torch.cuda.is_available() == false`

Установлен CPU-only PyTorch либо GPU не видна процессу. Проверить `nvidia-smi`,
затем версию torch из Qwen-окружения:

```powershell
& C:\izo-qwen-asr\Scripts\python.exe -c "import torch; print(torch.__version__, torch.version.cuda, torch.cuda.is_available())"
```

### Ошибка `nagisa` или `DyNet` в пути с кириллицей

Зависимость на текущем Windows-сервере не читает часть ресурсов из кириллического
пути. Runtime запускается через `C:\izo-qwen-asr`. Не удалять junction при живом
процессе и не запускать сервис напрямую из кириллического пути.

### Генерация зависает с `sdpa`

Принудительный `attn_implementation="sdpa"` зависал на проверенной Windows/CUDA
конфигурации. В `qwen_asr_service.py` намеренно используется штатная attention-
конфигурация модели. Не возвращать `sdpa` без отдельного benchmark.

### Первый запрос получает timeout

Дождаться зелёного `/health` и использовать 30 секунд для первого production-
теста. Тёплый запрос на текущем сервере занимает около двух секунд.

### CUDA OOM или замедление ComfyUI

Qwen и ComfyUI без явного назначения используют одну RTX 3090. На проверенном
сервере одновременная загрузка оставила ComfyUI около 386 МБ свободной torch VRAM:
одна генерация зависла в `KSampler`, а следующая ждала её в очереди. После остановки
Qwen и освобождения памяти контрольная генерация 1024x1024, 4 прохода завершилась
за 39 секунд.

Держать Qwen остановленным до появления отдельной RTX 4070. После установки второй
карты определить её CUDA-индекс через `nvidia-smi`, запустить Qwen с
`-CudaVisibleDevices "<индекс>"` и повторить голосовой и генерационный smoke-тесты.
Не выгружать активную модель ComfyUI во время пользовательской генерации.

### Порт 8001 занят неизвестным процессом

```powershell
Get-NetTCPConnection -LocalPort 8001 -State Listen | Select-Object OwningProcess
Get-Process -Id <PID>
```

Не завершать неизвестный процесс автоматически. Освободить порт осознанно либо
согласованно изменить порт в start-скрипте и настройке backend.

## 11. Предосторожности

- Не коммитить `.tools`, кеш модели, логи и PID.
- Не публиковать порт 8001 наружу.
- Не обновлять torch, transformers или qwen-asr прямо на production.
- Не запускать два Qwen runtime на одной GPU и одном порту.
- Не обходить защиту `-AllowSharedGenerationGpu` для постоянной работы.
- Не полагаться на автоматический выбор GPU на сервере с ComfyUI.
- Не очищать кеш весов во время работающего процесса.
- Не включать Qwen как единственный маршрут до живого теста русского аудио.
- Не выгружать ComfyUI при непустой очереди.
- Не считать зелёный `/health` полноценной проверкой распознавания: нужен WAV-тест.

## 12. Перенос на другой сервер

1. Склонировать тот же commit репозитория.
2. Установить проверенную версию Python и NVIDIA Driver.
3. Выполнить раздел чистой установки.
4. Дождаться полной загрузки модели.
5. Проверить `/health` и `/v1/models`.
6. Сохранить URL, модель и тайм-аут в админке.
7. Выполнить русский аудиотест из админки.
8. Проверить кнопку `Голос` в пользовательской вкладке.
9. Выполнить Quick gate.
10. Зафиксировать GPU, драйвер, времена и результат в журнале переноса.

Перенос считается завершённым только после сквозного теста
`браузер -> backend -> Qwen -> поле промпта`. Копирование старого `.venv` между
машинами не допускается: окружение создаётся заново из Git-манифеста.

## 13. Что ещё не автоматизировано

- создание окружения одной командой;
- полный lock всех транзитивных Python-зависимостей с hash-проверкой;
- предварительное скачивание и проверка контрольной суммы модели;
- Windows-автозапуск и автоматический restart;
- Linux/Docker deployment;
- живой WAV smoke-тест одной CLI-командой;
- автоматическое назначение отдельной RTX 4070.

Эти пункты являются следующей стадией hardening. До её завершения данная
инструкция обеспечивает повторяемую ручную установку, но не unattended deployment.
