# Админка ботов и каталог OpenRouter

Дата: 2026-07-16

**Контур применения — 17.10.2026.** Нижеследующие операции относятся к
установленному Windows runtime и требуют operator authorization, а не к
изолированным тестовым контейнерам. В Docker DEV/Shadow Telegram/MAX/платные
провайдеры должны оставаться выключенными; секреты Windows DPAPI не копируются
в образ. После Docker cutover действия и адреса перепроверяются по
`docs/docker-delivery-acceptance.md`, `docs/production-release-runbook.md`
и установленной конфигурации. Исторические шаги сами по себе не доказывают
текущую работоспособность внешних webhook.

## Назначение

Раздел `/admin/bots` управляет конфигурацией Telegram и MAX из trusted-admin
сессии. Он не запускает FRP, не меняет VPN и не переносит webhook после обычного
сохранения. Вкладка расположена между `Почта` и `Логи`.

Страница показывает:

- наличие и источник токена;
- результат безопасной проверки бота;
- сохранённый и фактически запущенный режим;
- состояние polling;
- готовность и вычисленный адрес webhook;
- наличие действующего Telegram webhook или подписок MAX;
- доступность публичного HTTPS;
- последнюю проверку и безопасную ошибку;
- предупреждение о конфликте со старым сервером.

## Хранение секретов

Секреты хранятся через Windows CurrentUser DPAPI отдельными файлами:

- `telegram_bot_token.dpapi.json`;
- `telegram_webhook_secret.dpapi.json`;
- `max_bot_token.dpapi.json`;
- `max_webhook_secret.dpapi.json`.

Корневой каталог задаётся `IZO_SECRET_DIR`. Без этой переменной используется
`%LOCALAPPDATA%\IZO_ASA\secrets`. Каталог обязан находиться за пределами
репозитория. Поэтому он не попадает в Git, SQLite и резервную копию проекта на
Яндекс.Диске.

DPAPI-файл привязан к Windows и учётной записи, которая его создала. Его нельзя
перенести на другой компьютер или расшифровать под другой служебной учётной
записью. Backend должен записывать секреты из процесса, запущенного под той же
учётной записью, под которой затем работает служба. Для `LocalService` настройку
следует выполнять уже через работающий backend этой службы.

API возвращает только факт настройки, источник и время изменения. Значение
секрета не возвращается и не записывается в audit log.

## Режимы

- `disabled`: получение обновлений на этом сервере выключено.
- `polling`: backend получает обновления фоновым запросом. Нужны токен,
  `pollingEnabled` и контролируемый перезапуск backend.
- `webhook`: платформа отправляет обновления на публичный HTTPS. Нужны токен,
  webhook-secret, публичный HTTPS и отдельная регистрация webhook.

Новая конфигурация по умолчанию использует `disabled`. Сохранение или замена
токена не запускает polling и не регистрирует webhook. Изменение режима требует
подтверждения. Сохранённый режим применяется только после контролируемого
перезапуска backend. Сам перезапуск не регистрирует webhook: это отдельная
подтверждённая операция в админке.

Если в `admin_settings.bot_integrations` ещё нет сохранённой конфигурации,
backend сохраняет совместимость с существующими переменными среды. После
первого сохранения источником несекретных настроек становится `admin_settings`,
а секреты после перезапуска читаются из DPAPI с приоритетом существующей
переменной среды.

## Настройка Telegram

1. Открыть `/admin/bots`.
2. Оставить режим `disabled`.
3. Ввести токен и нажать `Сохранить и проверить`.
4. Убедиться, что показаны ID и username бота.
5. Создать webhook-secret.
6. Проверить публичный адрес и вычисленный URL
   `https://izo.alikinas.ru/api/telegram/webhook`.
7. Остановить Telegram polling/webhook на старом сервере.
8. Отдельно зарегистрировать webhook или подтвердить polling и перезапустить
   backend.
9. Проверить `/start`, `/app`, `/help`, `/gallery`, `/settings`.

Перед polling админка показывает наличие действующего webhook. Удаление webhook
выполняется только отдельной кнопкой и не удаляет ожидающие обновления.

## Настройка MAX

1. Оставить режим `disabled`.
2. Сохранить и проверить токен через безопасный `/me`.
3. Проверить `MAX_API_BASE_URL`, deep link и типы событий.
4. Создать webhook-secret.
5. Проверить вычисленный URL `https://izo.alikinas.ru/api/max/webhook`.
6. Посмотреть существующие подписки.
7. Остановить получение обновлений на старом сервере.
8. Отдельно зарегистрировать подписку или включить polling с последующим
   контролируемым перезапуском.

## Административный API

Общие:

- `GET /api/admin/bots/config-v2`;
- `GET /api/admin/bots/status-v2`;
- `PUT /api/admin/bots/config-v2`.

Telegram:

- `PUT|DELETE /api/admin/bots/telegram/token-v2`;
- `POST /api/admin/bots/telegram/verify-v2`;
- `POST /api/admin/bots/telegram/webhook-secret-v2`;
- `POST /api/admin/bots/telegram/set-webhook-v2`;
- `POST /api/admin/bots/telegram/delete-webhook-v2`;
- `POST /api/admin/bots/telegram/configure-v2`.

MAX:

- `PUT|DELETE /api/admin/bots/max/token-v2`;
- `POST /api/admin/bots/max/verify-v2`;
- `POST /api/admin/bots/max/webhook-secret-v2`;
- `POST /api/admin/bots/max/set-webhook-v2`;
- `POST /api/admin/bots/max/delete-webhook-v2`.

Все endpoints требуют trusted-admin. Операции webhook требуют
`{"confirm": true}`.

## OpenRouter

`/admin/models` больше не ждёт последовательного живого опроса каталога.

1. Первый ответ использует последний каталог в памяти.
2. Если его нет, используется встроенный резервный каталог.
3. Живой image/video каталог и статус ключа обновляются одной фоновой задачей.
4. Параллельный повторный запуск не создаёт вторую полную задачу.
5. Временная ошибка не очищает последний успешный каталог.
6. После сохранения, замены или удаления ключа сбрасываются модели страницы,
   статус ключа и TTL авторизационно-зависимых каталогов.
7. Страница показывает источник, количество моделей, возраст, время успешного
   обновления и безопасную последнюю ошибку.

Управление:

- `GET /api/admin/openrouter/catalog/status-v2`;
- `POST /api/admin/openrouter/catalog/refresh-v2`.

## Восстановление после сбоя

1. Проверить `/api/health`.
2. Проверить, что служба запущена под ожидаемой Windows identity.
3. Открыть `/admin/bots` и проверить источник секретов.
4. Если DPAPI недоступен после смены Windows или identity, не переносить старые
   файлы: заново сохранить токены через работающую службу.
5. Оставить режимы `disabled`, пока не подтверждён старый сервер.
6. Проверить публичный HTTPS отдельно; проект не управляет FRP.
7. После восстановления явно зарегистрировать webhook либо включить polling.

## Чек-лист переключения

1. Сохранить токены.
2. Проверить Telegram и MAX.
3. Оставить режимы `disabled`.
4. Выполнить финальную синхронизацию базы.
5. Запустить туннель.
6. Проверить публичный HTTPS.
7. Остановить получение обновлений на старом сервере.
8. Зарегистрировать Telegram webhook.
9. Зарегистрировать MAX webhook.
10. Проверить команды и вход.
11. Проверить журнал ошибок.
12. Только после этого считать переключение завершённым.

## После установки новой Windows

1. Установить проект и backend-службу.
2. Настроить `IZO_SECRET_DIR` вне репозитория, если нужен нестандартный путь.
3. Запустить backend под окончательной служебной identity.
4. Заново сохранить все четыре секрета через `/admin/bots`.
5. Проверить чтение после контролируемого перезапуска.
6. Выполнить чек-лист переключения. Старые DPAPI-файлы не использовать.
