# Обязательные исправления каталога моделей в админке

Статус документа: **реализовано в коде, ожидает полного release-gate и проверки опубликованного сайта**.

Дата фиксации: 28.08.2026.

Область: `Админка -> Модели -> OpenRouter` — текст, изображения, видео и звук.

## Результат реализации 28.08.2026

В отдельной чистой ветке реализованы единая серверная экономика текста,
провайдерские даты выпуска, один главный переключатель текстовой модели,
синхронизация публикации с внутренним разрешением, явные `Показ` и `Режим` для
изображений и видео, унифицированные размеры элементов управления и отдельные
адаптивные карточки. Пользовательский каталог не возвращает скрытые модели,
учитывает тариф и помечает модель без подтверждённой цены недоступной.

Подтверждено до выпуска: 284 профильных серверных теста, frontend lint,
production build, тест публикации изображений, актуальные generated maps и
визуальный E2E текста/изображений/видео на 1920×1080, 1440×900, 1280×720,
1024×768, 768×1024 и 390×844. Платный запрос провайдеру ради проверки не
выполнялся; совпадение расчёта резервирования и окончательного списания
проверяется детерминированными серверными тестами.

Этот документ фиксирует недостатки уже установленной реализации. Ни один пункт
ниже нельзя считать выполненным только потому, что серверные тесты проходят или
страница открывается. Готовность подтверждается кодом, серверными правилами,
визуальной проверкой реального сайта и совпадением показанной цены с фактическим
списанием.

- [ ] Устранить разные размеры чекбоксов и радиокнопок.
- [ ] Полностью переработать вёрстку текстового каталога: текущая широкая и
  перегруженная таблица не соответствует согласованному представлению.
- [ ] Добавить цену за один миллион входных токенов провайдера в наших токенах.
- [ ] Добавить цену за один миллион выходных токенов провайдера в наших токенах.
- [ ] Добавить понятный ориентир стоимости одного миллиона русских символов в
  наших токенах с явно указанными допущениями.
- [ ] Добавить дату выпуска текстовых моделей в данные backend.
- [ ] Перенести дату выпуска в отдельное видимое место перед управляющими
  чекбоксами во всех каталогах.
- [ ] Унифицировать порядок и состав полей для текста, изображений и видео.

## 2. Правильная семантика публикации и доступа

### 2.1. Главный переключатель

У модели должен быть один понятный главный чекбокс:

`Показывать пользователям`.

Его поведение:

- выключен — модель отсутствует во всех пользовательских каталогах;
- включён — модель показывается пользователям;
- если тариф пользователя не даёт доступ, опубликованная модель остаётся
  видимой, но отображается недоступной;
- backend обязан повторно проверять публикацию и тарифный доступ, поэтому
  подделка запроса из браузера не должна разрешать запуск модели.

### 2.2. Текст

- [ ] Удалить отдельный видимый чекбокс `Чат`: для текстовой модели он
  дублирует единственную операцию.
- [ ] При включении главного чекбокса синхронно приводить внутреннее состояние
  текстовой модели к разрешённому для настройки тарифов состоянию.
- [ ] Оставить отдельными только тарифы `MINI`, `PLUS`, `PRO`, `BUSINESS` и выбор
  модели по умолчанию.

### 2.3. Изображения и видео

У одной модели могут быть разные операции, поэтому операционное управление
сохраняется, но не должно выглядеть как второй главный чекбокс.

- [ ] Главную публикацию показывать в строке модели.
- [ ] Операции вынести в явно подписанный блок `Режимы` или в раскрывающиеся
  секции: генерация по тексту, по изображению, редактирование, видео по тексту и
  другие поддерживаемые режимы.
- [ ] Не показывать анонимные соседние колонки `Публ.` и `Опер.` без пояснения.
- [ ] Если модель опубликована, но операция или тариф недоступны, показывать
  понятную причину недоступности.

## 3. Дата выпуска

Требуемое расположение в строке:

`Дата выпуска -> Публикация -> Модель -> Производитель -> Доступ -> Экономика`.

- [ ] Передавать `created` или `releaseDate` из каталога OpenRouter для
  текстовых моделей.
- [ ] Использовать только дату, полученную от провайдера; не придумывать её.
- [ ] При отсутствии значения показывать `дата не указана`.
- [ ] Использовать одинаковый формат даты, например `20.07.2026`.
- [ ] Не прятать дату мелкой подписью под названием модели.
- [ ] Проверить дату отдельно для текста, изображений и видео.

## 4. Экономика текстовых моделей

### 4.1. Что должно быть видно администратору

Для каждой модели необходимо показывать отдельными, читаемыми значениями:

- цену провайдера за 1 млн входных токенов, USD;
- цену провайдера за 1 млн выходных токенов, USD;
- себестоимость 1 млн входных токенов, RUB;
- себестоимость 1 млн выходных токенов, RUB;
- стоимость 1 млн входных токенов в наших продуктовых токенах;
- стоимость 1 млн выходных токенов в наших продуктовых токенах;
- ожидаемую выручку и маржу;
- среднюю фактическую стоимость ответа по накопленным данным;
- время последнего обновления цены и источник цены.

### 4.2. Формула

Расчёт должен использовать один серверный источник истины:

1. официальная цена OpenRouter в USD;
2. действующий курс USD/RUB;
3. банковский резерв, сейчас 30%;
4. цена одного нашего токена;
5. минимальная установленная маржа;
6. безопасное округление вверх.

Frontend не должен иметь собственную отличающуюся формулу. Backend должен
возвращать уже рассчитанные значения как минимум для:

- `inputPerMillionProductTokens`;
- `outputPerMillionProductTokens`;
- себестоимости в рублях;
- выручки;
- прибыли;
- фактической маржи;
- снимка курса, резерва и настроек маржи.

### 4.3. Дополнительные ориентиры

- [ ] Оставить пример `1000 входных + 500 выходных` только как дополнительный,
  а не как замену цене за миллион.
- [ ] Добавить приблизительный ориентир для одного миллиона русских символов.
- [ ] Явно написать, что символы и токены не равны друг другу, а оценка зависит
  от модели и соотношения входа/выхода.
- [ ] Не смешивать в одной мелкой строке доллары, рубли, выручку и прибыль.

## 5. Требования к вёрстке

- [ ] Все главные чекбоксы имеют одинаковый видимый размер.
- [ ] Все тарифные чекбоксы имеют одинаковый видимый размер.
- [ ] Радиокнопка модели по умолчанию не растягивается стилем текстового поля.
- [ ] Чекбоксы не наследуют общие `width: 100%` и `min-height: 34px` для input.
- [ ] Названия и идентификаторы модели не слипаются.
- [ ] Денежные и токенные значения выровнены и не соединяются в одну строку.
- [ ] Заголовок таблицы остаётся видимым при вертикальной прокрутке.
- [ ] Дата, публикация и название остаются видимыми при горизонтальной
  прокрутке на широких таблицах.
- [ ] На узких экранах текст, изображения и видео переходят в карточки или иной
  специально спроектированный мобильный вид.
- [ ] Раскрытие деталей не изменяет ширину основной таблицы.
- [ ] Для недоступного состояния используется не только цвет, но и текстовая
  причина.

## 6. Целевой порядок данных в строке

Общий порядок:

1. дата выпуска;
2. главный чекбокс `Показывать пользователям`;
3. название и технический идентификатор модели;
4. производитель;
5. режимы — только для изображений и видео;
6. тарифы;
7. техническая цена провайдера;
8. цена в наших токенах;
9. выручка, прибыль и маржа;
10. статистика генераций и фактических расходов;
11. выбор по умолчанию или раскрытие подробностей.

## 7. Серверные требования

- [ ] Публикация, операция и тарифный доступ проверяются backend, а не только UI.
- [ ] Неопубликованная модель не возвращается в пользовательском каталоге.
- [ ] Опубликованная, но недоступная по тарифу модель возвращается как видимая
  и недоступная с понятной причиной.
- [ ] Модель без подтверждённой цены нельзя разрешить для платного запуска.
- [ ] Расчёт наших токенов выполняется на сервере одной общей функцией.
- [ ] Значения в админке совпадают со снимком, используемым при резервировании и
  окончательном списании.
- [ ] Изменение курса, банковского резерва, цены токена или минимальной маржи
  приводит к пересчёту отображаемых значений.
- [ ] Для отсутствующих или устаревших цен показывается явный статус, а не ноль.

- [ ] Все чекбоксы и радиокнопки визуально унифицированы.
- [ ] Дата выпуска видна перед управляющими элементами.
- [ ] Для каждой оплачиваемой текстовой модели видна цена входа и выхода за
  миллион в наших токенах.
- [ ] Показаны отдельно себестоимость, выручка, прибыль и маржа.
- [ ] Текстовая вкладка читаема на компьютере и телефоне.
- [ ] UI, серверные разрешения и фактическое списание используют согласованные
  данные и формулу.
- [ ] Полные тесты и GitHub CI прошли.
- [ ] Новый релиз подтверждён локально и через публичный домен.
