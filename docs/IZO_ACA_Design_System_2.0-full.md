## Главное решение
Сохраняется сильная архитектура продукта: глобальные режимы, Composer слева, крупный Stage, компактная история и контекст выбранной работы. Система распространяется на изображения, видео, редактор, галерею, ленту, профиль и баланс токенов. Визуальный язык основан на спокойной тёмной рабочей среде, одном функциональном лаймовом акценте, умеренной типографике и адаптивных компонентах.

## Почему это рекомендуемый вариант
Решение опирается на устойчивые принципы современных систем: семантические цветовые роли Material 3, токены и типографическую иерархию Fluent, компонентную громкость Spectrum, рекомендации Apple по масштабированию текста и layout, WCAG 2.2 AA, а также container queries и fluid sizing в современном CSS \[1–24\]. Оно не зависит от краткосрочного тренда вроде тотального glassmorphism или неона.

# 1. Назначение, область и нормативный язык
## 1.1. Назначение
Документ определяет обязательные визуальные и поведенческие правила ИЗО ACA. Он используется дизайнерами, frontend-разработчиками, backend-разработчиками, авторами контента, QA, владельцем продукта и разработчиками ботов. Цель - исключить ситуацию, когда каждая вкладка или платформа выглядит как отдельный продукт.

## 1.2. Область действия
- Генерация изображений: По тексту, По изображению, Из нескольких.

- Редактор: По эскизу, Заменить область, Расширить, Удалить фон.

- Видео: Текст → видео, Изображение → видео, Начало и конец, По референсам.

- Галерея, проекты, пресеты, лента, профиль, баланс и подписка.

- Веб, Telegram Mini App, MAX Mini App, телефон, планшет и desktop.

## 1.3. Нормативные слова
| **Слово**        | **Смысл**                                                                         |
|------------------|-----------------------------------------------------------------------------------|
| ДОЛЖЕН / MUST    | Обязательное правило. Нарушение требует исправления или утверждённого исключения. |
| СЛЕДУЕТ / SHOULD | Рекомендуемое правило; отклонение допустимо только с аргументом и проверкой.      |
| МОЖЕТ / MAY      | Допустимая опция, если она не нарушает обязательные правила.                      |
| ЗАПРЕЩЕНО        | Решение, которое системно разрушает дизайн или доступность.                       |

## 1.4. Не входит в версию 2.0
- Окончательное переименование бренда.

- Полноценная светлая тема.

- Полноценный нелинейный видеоредактор.

- Маркетинговый сайт и рекламные баннеры.

- Точная дизайн-система нативных iOS/Android-приложений вне mini app.

# 2. Стратегические цели и критерии успеха
## 2.1. Продуктовые цели
> **1.** Новый пользователь создаёт первый результат без инструкции.
>
> **2.** Регулярный пользователь повторяет генерации и меняет параметры без потери контекста.
>
> **3.** Профессионал может держать приложение в узком окне и не терять ключевые функции.
>
> **4.** Мобильный пользователь видит результат, может изменить промпт и сразу потратить следующий токен.
>
> **5.** Видео воспринимается как часть того же продукта, а не отдельная неизвестная студия.
>
> **6.** Любой новый режим собирается из существующих компонентов.

## 2.2. UX-метрики
| **Метрика**              | **Что измеряется**                               | **Целевой сигнал**                        |
|--------------------------|--------------------------------------------------|-------------------------------------------|
| Time to first generation | Время от входа до запуска первого запроса        | Снижение без роста ошибок                 |
| First-task success       | Доля пользователей, завершивших первый сценарий  | Рост                                      |
| Repeat generation rate   | Сколько пользователей запускают вторую генерацию | Рост                                      |
| Prompt reuse rate        | Копирование/использование старого промпта        | Рост                                      |
| Editor handoff           | Переход результата в редактор                    | Рост у активных пользователей             |
| Mobile completion        | Завершение сценария на телефоне                  | Не ниже desktop с поправкой на устройство |
| Token comprehension      | Понимание, какой баланс будет списан             | Минимум ошибок и обращений                |
| Error recovery           | Повтор после ошибки или отмены                   | Рост успешного восстановления             |

## 2.3. Критерии визуального успеха
- Результат является самым крупным и ярким объектом.

- Нет микротекста и массовой жирности.

- Один экран не содержит двух одинаково сильных CTA.

- Внешний scroll desktop отсутствует в рабочем режиме.

- Компоненты сохраняют геометрию и роль на всех страницах.

- На 4K масштабируются текст, отступы и контролы, а не только пустое пространство.

# 3. Пользователи и ключевые задачи
## 3.1. Новичок
Ценность: быстро получить первый визуальный результат. Риск: перегрузиться терминами моделей, seed, FPS, силой guidance и ролями. Интерфейс ДОЛЖЕН показывать обязательный минимум и понятные примеры.

## 3.2. Регулярный пользователь
Ценность: повторять удачные настройки, сравнивать версии, использовать историю, переносить промпт и быстро создавать следующую работу. История и контекст ДОЛЖНЫ быть частью текущего рабочего пространства.

## 3.3. Профессионал
Ценность: предсказуемость, сохранение состояния, узкое окно, клавиатура, профессиональные параметры и редактирование. Сложность МОЖЕТ раскрываться постепенно, но не должна требовать прохождения мастера.

## 3.4. Мобильный пользователь
Ценность: короткая сессия, голос, редактирование промпта после результата, быстрый повтор и управление токенами. Mobile ДОЛЖЕН использовать отдельные состояния создания, результата и редактора.

## 3.5. Основные jobs-to-be-done
| **Когда...**              | **Я хочу...**                 | **Чтобы...**                                  |
|---------------------------|-------------------------------|-----------------------------------------------|
| Есть идея                 | описать её словами            | получить изображение или видео                |
| Есть фотография           | оживить или преобразовать её  | сохранить узнаваемость и управлять изменением |
| Есть несколько референсов | назначить роли                | собрать сцену без сложного промптинга         |
| Есть эскиз                | дорисовать его                | быстро перейти от наброска к визуалу          |
| Получен результат         | посмотреть историю и промпт   | сделать ещё или продолжить редактирование     |
| Нужна платная модель      | видеть стоимость и тип токена | понимать списание до запуска                  |

## 4.1. Визуальная метафора
- Тёмная среда - мастерская и монтажный стол.

- Изображение или ролик - освещённый рабочий объект.

- Composer - рабочая панель, а не анкета.

- Stage - место результата, а не рекламный баннер.

- Context Shelf - память текущей сессии.

- Лаймовый - энергия действия.

- Фиолетовый - социальный/премиальный слой, но не второй CTA.

## 4.2. Непереговорные принципы
### Контент важнее интерфейса
Панели и действия не уменьшают медиа без функциональной причины.

### Один функциональный акцент
Зелёный означает действие, выбор или прогресс.

### Одна задача - один CTA
Две яркие основные кнопки на одном экране запрещены.

### Текст не уменьшается ради вместимости
Меняется сетка, подпись или представление.

### Сложность раскрывается постепенно
Модели и технические параметры находятся в профессиональном уровне.

### Контекст сохраняется
Вкладки сохраняют промпты, источники и настройки.

### Цвет не единственный сигнал
Выбор меняет фон, рамку, текст и/или знак.

### Мобильный сценарий самостоятельный
Mobile не является сжатым desktop.

### Редактор имеет canvas-архитектуру
Инструменты и свойства подчинены холсту.

### Доступность встроена
Focus, contrast, reflow и target size проверяются до релиза.

| Личная работа        | Галерея · Проекты · Пресеты                                          | Хранить и продолжать          |
| Социальный слой      | Лента                                                                | Публиковать и смотреть работы |
| Аккаунт              | Профиль · Подписка · Баланс                                          | Управлять доступом и оплатой  |

## 5.2. Глобальные режимы
На desktop верхние вкладки ДОЛЖНЫ быть видимы одновременно: По тексту, По изображению, Из нескольких, Редактор, Видео. Внутри «Видео» находятся четыре собственных режима. На mobile вкладки располагаются в горизонтальной ленте, но не уменьшаются до микротекста.

## 5.3. Состояние вкладки
- Промпт и исходники сохраняются при переходе.

- Результат и история режима сохраняются.

- Очистка выполняется только явным действием «Начать заново».

- Если работа открыта из истории, активируется режим, в котором она была создана.

## 7.1. Composer
- Ширина Full HD: 410–430 px.

- На 1366 px: 360–390 px.

- На 2K/4K: 460–560 px через clamp().

- Прокручивается только центральное содержимое.

- Заголовок и CTA остаются на месте.

- CTA не перекрывает формат и параметры.

## 7.2. Stage
- Занимает максимум площади.

- Медиа показывается целиком через object-fit: contain.

- Верхняя служебная панель не используется.

- Под медиа остаются только главные действия.

- Full screen и fit могут быть иконками в углу медиа.

## 7.3. Actions
Для изображений и видео базовые действия: Скачать и Поделиться. Редактировать показывается только там, где продолжение действительно существует. Все системные действия - Добавить в проект, Опубликовать, Удалить, Начать заново - находятся в контекстном меню выбранной работы.

## 7.4. Context Shelf
- История занимает большую часть ширины.

- Подписи форматов под миниатюрами не нужны; формат читается по форме.

- Промпт ограничен 2–3 строками.

- Разворачивание меняет только нижнюю полку.

- История прокручивается колесом и свайпом.

## 8.4. Ограничение лаймового
- Одна крупная лаймовая CTA на экран.

- Активная вкладка может быть лаймовой.

- Выбранный компактный контрол получает лаймовый контур и слабый фон.

- Не использовать лаймовые рамки вокруг всех секций.

# 14. Поля и управляющие компоненты
## 14.1. Textarea промпта
- 16–20 px в зависимости от viewport.

- Вес 400, line-height 1.5–1.6.

- Очистка появляется только при наличии текста.

- Крестик компактный, полупрозрачный, 32×32 внутри touch target.

- Счётчик находится справа снизу.

- Ctrl/Cmd + Enter запускает генерацию.

- Поле не использует постоянную лаймовую рамку; лайм появляется на focus.

## 14.2. Помощники промпта
На Full HD четыре кнопки ДОЛЖНЫ помещаться в один ряд. На 390 px они также помещаются в один ряд. Ниже 350 px допустима сетка 2×2. Горизонтальный scroll помощников не является основным решением.

## 14.3. Segmented control
- Форматы 1:1, 9:16, 16:9, 3:2 видны на основном уровне.

- На mobile формат не прячется в bottom sheet.

- Выбор обозначается контуром, слабым фоном и цветом текста.

## 14.4. Select
- Высота 44–52 px.

- Label всегда видим.

- Неподдерживаемый параметр скрывается, а не просто disabled.

- Длинные названия модели допускают сокращённое display label и полное имя в tooltip.

## 14.5. Slider
- Текущее значение выводится числом.

- Смысл объясняется словами по краям.

- Для «Силы изменения»: Сохранить исходник ↔ Сильно изменить.

- Для видео: Спокойное движение ↔ Динамичное.

## 14.6. Switch
Switch используется только для бинарной настройки, например «Звук в ролике». Он не заменяет выбор из нескольких вариантов.

# 15. Изображения, видео и история
## 15.1. Stage
- Медиа всегда показывается целиком.

- Crop допускается только как явная функция пользователя.

- Размытая копия может использоваться как фон вокруг медиа с фиксированным затемнением.

- Действия не должны закрывать значимую часть результата.

## 15.2. История
- Миниатюры сохраняют реальные пропорции.

- Нет подписей формата под каждым элементом.

- Длительность видео показывается маленьким бейджем внутри poster frame.

- Выбранная работа получает лаймовый контур.

- Стрелки находятся поверх краёв, а не занимают отдельные колонки.

- Wheel и swipe прокручивают историю горизонтально.

## 15.3. Prompt Context
- Компактное состояние: 2–3 строки.

- Метаданные одной строкой.

- Кнопки: Копировать, Использовать промпт/настройки.

- Меню ⋯: проект, публикация, удаление, начать заново.

- Развёрнутое состояние имеет внутренний scroll, а не модальное окно.

## 15.4. Системные действия
Под Stage находятся только Скачать и Поделиться. Редактировать показывается только для изображений и только если переход действительно продолжает текущую работу. В видео отдельная команда редактирования не показывается до появления видеоредактора.

# 17. Пустые, загрузочные и ошибочные состояния
## 17.1. Empty state
До первой генерации Stage не показывает случайную готовую работу. Он объясняет текущий режим через SVG-сцену. По команде «Как работает» схема доступна повторно без удаления промпта.

| **Режим**           | **Схема**                                       |
|---------------------|-------------------------------------------------|
| По тексту           | Текст → электронный модуль → чертёж изображения |
| По изображению      | Исходник + промпт → модуль → результат          |
| Из нескольких       | Основа + лицо + одежда + стиль → модуль → сцена |
| Редактор            | Эскиз/маска → модуль → изменённое изображение   |
| Текст → видео       | Текст → модуль → кинолента                      |
| Изображение → видео | Кадр + движение → модуль → ролик                |
| Начало и конец      | Кадр 1 → временная линия → кадр 2               |
| По референсам       | Персонаж + окружение + стиль → модуль → ролик   |

## 17.2. Loading
Если backend не передаёт реальный процент, запрещено показывать фальшивые 64%. Используется этап: Подготовка → Композиция/движение → Детали/кадры → Звук → Завершение. При наличии реального прогресса допускается progress bar.

## 17.3. Ошибка
- Сообщить, что произошло.

- Сообщить, списаны ли токены и будут ли возвращены.

- Предложить Повторить или Изменить параметры.

- Сохранить введённые данные.

## 18.1. Принцип
Motion показывает причинно-следственную связь и состояние системы. Он не является постоянным украшением. Apple и Fluent рекомендуют использовать движение последовательно и учитывать reduced motion \[9–12\].

## 18.2. Временные токены
| **Событие**       | **Длительность** | **Easing**               |
|-------------------|------------------|--------------------------|
| Hover             | 120–160 ms       | ease-out                 |
| Pressed           | 80–120 ms        | ease-in                  |
| Tab switch        | 140–180 ms       | ease-out                 |
| Popover/sheet     | 180–240 ms       | cubic-bezier(.2,.8,.2,1) |
| Result transition | 220–320 ms       | ease-out                 |
| Empty-state cycle | 6–8 s            | linear + ease segments   |

## 18.3. Запреты
- Не масштабировать обычные кнопки на hover.

- Не использовать бесконечное неоновое мерцание.

- Не анимировать каждую рамку.

- Не задерживать доступ к результату cinematic-переходом.

- Уважать prefers-reduced-motion.

## 20.5. Генерация
Показываются реальные этапы backend. Если API возвращает очередь и приблизительное время, они отображаются. Поддельный линейный процент запрещён.

# 21. Редактор
## 21.1. Архитектура desktop
| **Зона**   | **Содержимое**                        |

- Заменить область: маска + описание.

- Расширить: направления и outpainting.

- Удалить фон: автоматический результат, ручное уточнение по необходимости.

## 21.3. Mobile editor
- Canvas занимает максимум.

- Инструменты в горизонтальной ленте.

- Undo/Redo всегда доступны.

- Глобальная bottom nav скрыта.

- Prompt bar открывается без потери холста.

# 22. Галерея, лента, профиль и проекты
## 22.1. Галерея
- Фильтры: Все, Созданные, Загруженные, Редактор, Видео.

- Карточки сохраняют пропорции.

- Действия появляются при выборе, а не постоянно.

- Поиск по названию и промпту.

## 22.2. Лента
- Фиолетовый допустим как социальный акцент.

- Работа остаётся главным объектом.

- Лайк, автор, использовать настройки, открыть работу.

- Лента не наследует рабочие панели Composer.

## 22.3. Профиль
- Два баланса токенов.

- Подписка и дата действия.

- Пресеты и проекты.

- Настройки платформы и доступность.

## 22.4. Проекты
Проект - контейнер связанной работы: исходники, генерации, видео, редактор и публикации. Он не должен смешиваться с историей текущего режима.

# 23. Mobile, tablet, desktop, 2K и 4K
> **Иллюстрация:** Рисунок 11. Mobile использует отдельные состояния.

Рисунок 11. Mobile использует отдельные состояния.

## 23.1. Breakpoint не равен устройству
Решение принимается по доступному контейнеру, а не по user-agent. Container queries применяют стили на основе размера компонента, что устойчивее при узком desktop-окне, split-screen и mini app \[21\].

## 23.2. Диапазоны
| **Контекст**     | **Ширина** | **Схема**                            | **Базовый текст** |
|------------------|------------|--------------------------------------|-------------------|
| Small mobile     | 320–374    | 1 колонка; 2×2 помощники             | 16 px             |
| Mobile           | 375–767    | Создание/результат/редактор отдельно | 16–17 px          |
| Tablet portrait  | 768–899    | Вертикальный поток                   | 16–17 px          |
| Tablet landscape | 900–1199   | Узкий Composer + Stage               | 16–17 px          |
| Laptop           | 1200–1599  | Полный каркас, компактная плотность  | 15–17 px          |
| Full HD          | 1600–2199  | Эталонная схема                      | 16–18 px          |
| 2K/4K            | 2200+      | Масштабированные токены              | 18–20 px          |

## 23.3. 4K
- Панель 500–560 px.

- CTA 62–68 px.

- История 140–160 px.

- Текст 18–20 px.

- Stage имеет max-width/max-height, чтобы не разрывать композицию.

## 23.4. Browser zoom
Проверка обязательна при 80%, 100%, 125%, 150%, 200% и 400% там, где применимо. WCAG требует увеличение текста до 200% без потери функции \[17\].

# 24. Доступность и управление
## 24.1. Цель
Цель - WCAG 2.2 AA. Для target size внутренний продуктовый стандарт выше минимума AA: 44×44 CSS px, хотя WCAG 2.2 AA устанавливает минимум 24×24 с исключениями \[15\].

| **Область**       | **Требование**                                |
|-------------------|-----------------------------------------------|
| Text contrast     | 4.5:1; large 3:1                              |
| Non-text contrast | 3:1 для границ/состояний, если они необходимы |
| Target size       | 44×44 продуктовый минимум                     |
| Focus             | Видимое кольцо; не скрывается sticky CTA      |
| Resize            | 200% без потери функции                       |
| Reflow            | Ключевые задачи при 320 CSS px                |
| Color             | Не единственный сигнал                        |
| Keyboard          | Полный сценарий без мыши                      |
| Motion            | prefers-reduced-motion                        |
| Hover content     | Закрываемое, удерживаемое, доступное при zoom |

## 24.2. Клавиатура
| **Команда**          | **Действие**                               |
|----------------------|--------------------------------------------|
| Ctrl/Cmd + Enter     | Запустить генерацию                        |
| Esc                  | Закрыть overlay / отменить локальный режим |
| ← / →                | Переключить историю при focus              |
| Ctrl/Cmd + Z         | Undo                                       |
| Ctrl/Cmd + Shift + Z | Redo                                       |
| Space                | Play/Pause видео при focus плеера          |

## 24.3. Sticky элементы
CTA и нижняя навигация не должны перекрывать focus. Используются scroll-padding и резервирование высоты. WCAG 2.2 требует, чтобы focused element не был полностью скрыт авторским контентом \[20\].

# 25. Контент-дизайн и терминология
## 25.1. Тон
Спокойный, точный, результативный. Не рекламный, не детский и не технически перегруженный. Пользователь видит действие и результат, а не внутреннее устройство модели.

| **Не использовать** | **Использовать**                           |
|---------------------|--------------------------------------------|
| Влияние промпта     | Сила изменения                             |
| Сборка              | Из нескольких                              |
| По фото             | По изображению                             |
| Вариации            | Создать похожие / в меню                   |
| Маска               | Заменить область                           |
| Режим Профи         | Профессиональные настройки                 |
| В промпт            | Использовать промпт                        |
| Повторить           | Сгенерировать ещё / Использовать настройки |
| Сохранить           | Скачать / В галерею / В проект             |
| Готово              | Показывать только как статус, если нужен   |

## 25.2. Подсказки
- Короткие и привязаны к решению.

- Не повторяют label.

- Не требуют hover на touch-устройстве.

- Могут исчезать после освоения.

## 25.3. Ошибки
Формула: Что произошло → Что сохранено/списано → Что делать. Пример: «Не удалось создать ролик. Премиум-токены не списаны. Повторите или выберите другую модель».

# 26. Запрещающие правила
> **1.** Не использовать более одного крупного функционального акцента.
>

## 28.1. Usability-план
