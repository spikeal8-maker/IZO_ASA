# Студия видеогенерации

Дата: 2026-07-15

Статус: пользовательская страница, серверная очередь, приватное хранение результата, общая медиагалерея и восстановление истории реализованы. Платный smoke конкретных production-моделей выполняется перед их включением пользователям.

Нормативная визуальная система проекта находится в `izo-asa-design-system-20260716.md`. Видеостудия является первой страницей, переведенной на последовательность `Composer -> Stage -> Actions -> History + Context`.

## Пользовательский сценарий

Страница доступна по `/video` и открывается верхней вкладкой `Видео`. На телефоне рабочая область с видеоплеером идет первой, параметры раскрываются ниже. На компьютере параметры и плеер расположены рядом.

Доступны четыре режима:

| Режим | Входные данные |
|---|---|
| По тексту | промпт |
| Из изображения | промпт и стартовый кадр |
| Первый и последний кадр | промпт, первый и последний кадр |
| По референсам | промпт и поддерживаемое моделью число изображений |

Для выбранной модели интерфейс показывает только опубликованные длительности, разрешения, пропорции и поддержку аудио. Окончательная пользовательская цена запрашивается у backend до запуска и повторно рассчитывается тем же маршрутом перед списанием. Черновик параметров хранится локально, а история генераций берется из базы.

В режиме с изображением блок исходников появляется непосредственно в Composer до промпта. Кадр можно загрузить с устройства или выбрать из общей галереи. На телефоне Stage расположен первым и сохраняет выбранный формат `16:9`, `9:16` или `1:1`; элементы Composer и кнопка генерации не перекрывают рабочую область.

В профиле на вкладке моделей пользователь может скрыть ненужные видеомодели и назначить видимые модели на профили `Быстро`, `Стандарт` и `Максимум` отдельно для каждого режима. Выбор хранится в пользовательском браузере и применяется видеостудией. Полный серверный контроль тарифов остается на backend.

## Серверный контракт

| Endpoint | Назначение |
|---|---|
| `GET /api/video/config` | разрешенные пользователю модели, режимы и текущие параметры |
| `POST /api/video/estimate` | серверная оценка токенов без списания |
| `POST /api/video/generate` | валидация, резерв токенов и отправка задания |
| `GET /api/video/jobs/{id}` | polling одного задания и финализация результата |
| `GET /api/video/history` | история владельца и обновление активных заданий |
| `GET /api/video/media/{id}` | авторизованная выдача сохраненного MP4 |
| `POST /api/gallery/videos/{id}/favorite` | избранное для видео владельца |
| `DELETE /api/gallery/videos/{id}` | удалить MP4 и скрыть видео из галереи |
| `GET /api/gallery/items` | единая курсорная выдача изображений и видео |

OpenRouter вызывается через `POST /api/v1/videos`, состояние читается через `GET /api/v1/videos/{id}`. Локальная база является источником состояния пользовательского задания: закрытие вкладки или перезапуск frontend не теряют его. Готовый файл копируется с временного URL провайдера в приватное медиахранилище проекта.

Таблица `videos` отделяет медиагалерею от очереди `jobs`: задание сохраняется для истории и бухгалтерии, а видео можно удалить из пользовательской галереи независимо. Backfill при открытии истории или галереи идемпотентно добавляет ранее завершенные задания с существующим `localFile`, поэтому обновление схемы не теряет уже созданные ролики.

## Биллинг и защита

1. Цена вычисляется только backend по каталогу SKU, курсу, резерву, цене токена и минимальной марже из админки.
2. Перед отправкой задания списывается ровно показанная и подтвержденная цена.
3. Ошибка отправки или окончательная ошибка задания возвращает списание идемпотентно.
4. После завершения сохраняется `usage.cost` и фактическая себестоимость для бухгалтерии и расчета маржи. Пользовательская цена после запуска не меняется и скрытого дополнительного списания нет.
5. Модель должна быть включена для режима и тарифного плана пользователя; frontend не может обойти эту проверку.
6. Медиа и статус доступны владельцу задания и администратору, а не по открытому пути файла.

### Модель без опубликованной ставки

Отсутствие `pricingSkus` больше не блокирует генерацию. Backend выбирает цену в
строгом порядке:

1. точная ставка каталога, включая актуальные SKU OpenRouter в центах
   `cents_per_video_output_second_*`;
2. средняя фактическая стоимость этой модели для того же режима, разрешения,
   пропорции и аудио с защитным резервом;
3. история сопоставимых видео других моделей с увеличенным резервом;
4. консервативная стартовая ставка по разрешению, режиму и наличию аудио.

После трех завершенных генераций модель автоматически переходит на собственную
историю. В `openrouterBilling` сохраняются `pricingSource`, `pricingFallback` и
`pricingSampleCount`, поэтому администратор видит, откуда взялась оценка.
Начальная цена является окончательной для уже запущенного задания; фактическая
стоимость меняет только будущие оценки и финансовую аналитику.

## Повторное развертывание

1. Настроить рабочий ключ OpenRouter в существующей вкладке `Админ -> Модели -> OpenRouter`.
2. Обновить каталог, раскрыть `Видео OpenRouter` и включить только проверенные модели, режимы и тарифы.
3. Проверить глобальную цену токена, минимальную маржу и текущий валютный курс.
4. Убедиться, что выбранный тариф содержит `video.enabled=true` и ненулевые video slots.
5. Установить frontend-зависимости и выполнить `npm run build` в `frontend`.
6. Перезапустить backend из корня: `python -m uvicorn backend.main:app --host 127.0.0.1 --port 8000`.
7. Авторизованно открыть `/video`, проверить `GET /api/video/config`, расчет стоимости и историю.
8. До выдачи пользователям провести одно платное задание каждого включаемого режима и сверить длительность, разрешение, MP4 и `usage.cost`.

## Диагностика

- Пустой список моделей: проверить ключ, живой video catalog OpenRouter и включение модели в админке.
- `403`: тариф или модель не разрешены пользователю.
- `409`: недостаточно токенов или исчерпаны video slots.
- Задание долго активно: открыть историю; polling продолжится. Проверить OpenRouter job id и ответ провайдера в записи задания.
- Провайдер завершил задание ошибкой: пользователю показывается локальная ошибка, резерв возвращается, остальные настройки страницы сохраняются.
- Видео завершено, но не открывается: проверить загрузку временного provider URL и наличие `localFile` в записи задания.
- Видео есть в истории, но нет в галерее: открыть `/api/video/history` или `/api/gallery/items` и проверить, что физический `localFile` существует; backfill не восстанавливает отсутствующий файл.
- Модель не видна пользователю: проверить тарифный доступ в админке, затем пользовательскую видимость в `Профиль -> Модели -> Видеомодели`.

## Checkpoint V6: понятные параметры и мобильный сценарий

V6 закрепляет последовательность действий и устраняет визуальные скачки в

Дата: 2026-07-17.

V7 завершает упрощение Composer и закрепляет безопасное поведение результата:

- около заголовка промпта остается ровно один значок справки. Наведение не
  открывает всплывающую плашку; по нажатию появляется модальное руководство
  поверх всей страницы с пятью шагами создания первого ролика;
- длительность перенесена в строку заголовка промпта. Компактный select содержит
  значок часов и не меняет положение при включении или выключении звука;
- звук оформлен одной полноширинной строкой под промптом: название, выбранная
  модель, переключатель, итоговая стоимость и стоимость в секунду находятся в
  одной геометрически стабильной области;
- интерфейс использует итоговую серверную оценку выбранной конфигурации. В нем
  больше нет отдельной клиентской надбавки или второго параллельного запроса,
  который мог показывать пользователю противоречивую цену;
- блоки формата и качества сближены и не разделены лишней линией. Пиктограмма
  `16:9` имеет реальную широкую форму, а не квадратный условный знак;
- действие `Очистить предпросмотр` скрывает результат только со Stage и сохраняет
  его в истории. Отдельное действие `Удалить из галереи` остается явным и
  требует подтверждения перед удалением сохраненного файла;
- пустая область исходного кадра целиком открывает выбор файла, а не требует
  попадания в маленькую внутреннюю кнопку;
- на телефоне исходные материалы находятся перед Stage, меню режима имеет слой
  ниже канонической верхней панели, а кнопка `Создать видео` закреплена у нижнего
  края с учетом safe-area;
- подписи режимов уточнены: `Создать сцену по тексту` и `Оживить изображение`.

Регрессионный сценарий `frontend/e2e-video-studio-layout.mjs` дополнительно
проверяет единственный знак справки, пять пунктов руководства и его верхний
слой, длительность в заголовке, стабильность звукового переключателя, форму
`16:9`, полный клик по исходному кадру, сохранение истории после очистки Stage,
мобильный порядок блоков, sticky-кнопку и слои мобильного меню/главной шапки.

Фактические проверки V7:

- `npx vite build`: успешно;
- `node e2e-video-studio-layout.mjs`: успешно для `1920x1080`, `1920x900`,
  `3840x2160` и `390x844`;
- горизонтального переполнения и обрезки нижних действий на проверенных размерах
  не обнаружено;
- временный preview используется только для QA и должен быть остановлен после
  публикации канонической сборки на `127.0.0.1:5173`.

## Checkpoint V8: мгновенная обратная связь и фиксированная цена

Дата: 2026-07-19.

V8 закрывает задержку между нажатием кнопки и появлением задания, а также
устраняет расхождение показанной и итоговой цены:

- сразу после нажатия `Создать видео` в Stage и истории появляется локальное
  состояние `Отправляем задачу`; ответ OpenRouter больше не оставляет пустой
  экран на время сетевого запроса;
- активное задание и выбранный для просмотра результат разделены. Пока новый
  ролик создается, пользователь может открыть любое старое видео и вернуться к
  прогрессу одной компактной кнопкой;
- polling активного задания выполняется раз в три секунды, а история сохраняет
  единственную карточку задания после замены локального id серверным;
- после подтверждения списания сервером обновляется баланс в общей верхней
  панели;
- нативный белый `select` длительности заменен доступным темным listbox. Все
  значения написаны полностью: `4 секунды`, `5 секунд` и так далее;
- основные форматы занимают четыре ячейки, а дополнительные раскрываются
  компактной кнопкой со счетчиком справа. Расстояние до качества уменьшено;
- цена, полученная от `/api/video/estimate`, совпадает с `tokenCost` ответа
  `/api/video/generate`. Она остается окончательной после завершения задания;
  `usage.cost` используется только для финансовой аналитики;
- модель не требует предыдущих генераций для оценки: используется точная ставка
  каталога, а при ее отсутствии — стартовая серверная ставка с последующей
  калибровкой по фактическому `usage.cost`.
